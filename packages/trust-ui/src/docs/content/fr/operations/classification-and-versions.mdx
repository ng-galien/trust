```gherkin fragment
# language: en
@trust-dsl:1 @operation:git.head-read @version:1.0.0 @x-family:software-delivery @x-nature:observe
Feature: Read Git HEAD and working tree

  Reads the current revision and whether the working tree is clean.
```

## Tags d'identité

| Tag | Règle |
| --- | --- |
| `@operation:<domain>.<action>` | exactement un. Deux segments en minuscules séparés par un point ; chaque segment est alphanumérique avec tirets optionnels (`git.head-compare`, `docker.image-build`). Le domaine regroupe le catalogue ; l'action nomme ce qui est fait |
| `@version:<major>.<minor>.<patch>` | exactement un, une version SemVer valide ; les préversions et métadonnées de construction suivent les règles SemVer |
| `@trust-dsl:1` | exactement un, valeur `1` — la version du langage |
| tout le reste | doit être un tag de classification `@x-` ; sinon `Tag "…" is outside the closed Operation grammar` |

L'ordre des tags est libre. Le catalogue écrit `@trust-dsl:1 @operation:… @version:…`.

## Classification `@x-<key>:<value>`

Libre, répétable, opaque pour l'exécution : `@x-family:software-delivery`, `@x-nature:observe`, `@x-team:platform @x-team:sre`. La clé commence par une lettre minuscule (segments avec tirets autorisés) ; la valeur n'a ni espace ni deux-points. Le compilateur les regroupe par clé (`classification: { family: ["software-delivery"], nature: ["observe"], team: ["platform", "sre"] }`), doublons supprimés.

L'écran du catalogue utilise `family` et `nature` pour ses facettes ; tout le reste est à vous de le définir.

## Titre et description

`Feature: <title>` est le titre humain, copié tel quel. Le bloc de texte libre en dessous est la **description** : ce que l'Opération observe, ses hypothèses, ce que signifie une sortie acceptée. Elle est affichée sur l'aperçu de l'Opération et dans le graphe des Procédures qui l'utilisent. Elle n'est jamais exécutée. L'indentation et les lignes vides répétées sont normalisées.

## Versions

- L'identité d'une entrée de catalogue est `name@version` (`git.head-read@1.0.0`). Le catalogue est un répertoire de fichiers `.feature`, une entrée par fichier ; le même `name@version` dans deux fichiers est refusé.
- L'interface publie une nouvelle version d'Opération dans `<name>@<version>.feature`, sans remplacer les précédentes. Une identité/version ou un fichier existant ne peut pas être écrasé. Une version publiée ne peut pas être supprimée ; les modifications d'un brouillon peuvent être annulées.
- Une Procédure référence une Opération ou une Procédure enfant avec `name@selector` : une version exacte ou une plage node-semver standard telle que `^1.2.3` ou `~1.2.3`. La version correspondante la plus élevée doit passer les contrôles de compatibilité ; TRUST ne se rabat pas silencieusement sur une version plus ancienne. Les étiquettes telles que `latest` ne sont pas prises en charge.
- Un nouveau Plan résout et épingle toute la composition récursive. Les publications suivantes ne modifient ni ses Checks, ni ses enfants différés, ni sa reprise, ni les générations de remplacement de ses enfants. Le catalogue regroupe chaque identité une seule fois ; la fiche permet de choisir sa version exacte.
- Les marques « exécutable » (✓ sur le catalogue, sur l'écran Environnement) sont calculées par entrée de catalogue contre les valeurs que chaque Environnement déclare.

<Callout kind="rule">
  Les versions publiées sont immuables. Une référence flottante peut sélectionner une version plus récente pour un nouveau Plan, mais la composition d'un Plan engagé reste fixe.
</Callout>

<Details title="Opération compilée et digest" expert>
Le compilateur émet `trust.compiled-operation@1` avec : `operation`, `version`, `title`, `description?`, `source` (le Gherkin normalisé), `input`, `environment`, `produced` (JSON Schemas), `steps` (ordonnées, typées), `produce` (`{ language: "jsonata", expression }`) et `classification?`. L'onglet **Contrat JSON** de l'interface montre cet objet.

Le compilateur de Procédure calcule un **digest** SHA-256 de la sémantique de chaque Opération embarquée : tout ce qui précède sauf `source`, avec la projection remplacée par son arbre syntaxique abstrait dépouillé des positions. Les commentaires, l'indentation et le formatage JSONata ne changent donc pas le digest ; le titre, la description, la classification, l'interface, les étapes et le sens de la projection, si.
</Details>
