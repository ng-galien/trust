Le `Background` d'une Opération est son contrat : ce qu'une Procédure lie (Input), ce qu'un <Term id="environment">Environnement</Term> fournit (Environment), ce qu'un Check peut tester (Produced fields). Tout est typé, nommé en lower camel case et fermé — aucune valeur optionnelle, aucune clé libre. Une quatrième table optionnelle, `Credentials`, nomme les secrets de l'Environnement que ses étapes utilisent.

> L'Input vient du Check, l'Environment du contexte d'exécution, les Produced fields vont au Check.

```gherkin fragment title="Les trois déclarations"
  Background: Operation interface
    Given Environment
      | name          | type      |
      | workspaceRoot | directory |
    And Input
      | input   | type      | cardinality |
      | project | reference | one         |
    And Produced fields
      | field        | type      | cardinality | domain                |
      | headRevision | reference | one         | any                   |
      | workingTree  | string    | one         | enum "clean", "dirty" |
```

## Types de valeur

Les quatre mêmes types servent pour Input et Produced fields ; Environment a trois types de valeur d'exécution.

| Type | Signification | Validé comme |
| --- | --- | --- |
| `string` | texte libre | une chaîne JSON |
| `number` | un nombre | un nombre JSON |
| `instant` | un point dans le temps | une chaîne date-time RFC 3339 |
| `reference` | un identifiant de quelque chose hors de TRUST (une révision, une clé de ticket, un nom de projet) | une chaîne non vide |
| `directory` *(Environment seulement)* | l'endroit où vivent les projets | un chemin absolu du système de fichiers |
| `url` *(Environment seulement)* | l'URL de base d'un service | une URL `http(s)` sans credentials embarqués |
| `string` *(Environment seulement)* | un réglage non secret de requête ou d'exécution | une chaîne non vide sans NUL |

La **cardinalité** est `one` (un scalaire) ou `many` (un tableau du type). Il n'y a pas de valeur optionnelle : chaque valeur Input et Environment déclarée est requise, et l'Opération doit produire chaque champ déclaré.

## Environment

```gherkin fragment
    Given Environment
      | name          | type      |
      | workspaceRoot | directory |
      | serviceUrl    | url       |
      | apiMode       | string    |
```

- Requis, une fois, au moins une ligne. L'en-tête est exactement `| name | type |`.
- Un `directory` nomme **l'endroit où vivent tous les projets**, pas un projet. Une étape Shell ou File le restreint à un projet avec `and Input "<name>"` : l'Input doit être une chaîne nommant un répertoire directement sous la racine — pas de séparateur de chemin, pas de `..`, pas de lien symbolique hors de la racine. Sans cette clause, l'étape s'exécute dans le répertoire lui-même.
- Une `url` est la base de toute méthode HTTP ; des clauses structurées peuvent ajouter des segments encodés et des paramètres de query.
- Un `string` fournit des valeurs non secrètes de query, de header ou de corps Text HTTP.
- Les valeurs viennent de l'Environnement choisi à l'admission (en réel) ou de l'environnement courant de l'interface (onglet **Exécuter**). Une Opération est *exécutable* sur un Environnement quand l'Environnement déclare chaque nom dont elle a besoin — c'est ce que montrent les marques ✓ du catalogue et de l'écran Environnement.

## Input

```gherkin fragment
    And Input
      | input        | type      | cardinality |
      | project      | reference | one         |
      | baseRevision | reference | one         |
      | documents    | reference | many        |
```

- Optionnel (une Opération peut n'avoir besoin d'aucun Input), au plus une fois. L'en-tête est exactement `| input | type | cardinality |`.
- D'où viennent les valeurs : dans un Plan, la phrase du Check lie chaque Input à un rôle de contexte du Plan (`on "project" as Input "project"`, `using "baseline" as Input "baseRevision"`). Chaque Input doit être lié exactement une fois. Dans l'interface, **Simuler** et **Exécuter** vous les demandent.
- Ce qu'un Input peut alimenter : un argument Shell, la restriction de répertoire, une valeur de chemin/query/header/corps Text HTTP, le corps JSON complet, un corps JSONata, et la racine `input.<name>` de Produce.
- Partout où une étape a besoin d'**une chaîne**, l'Input doit être de cardinalité `one` et de type `string`, `instant` ou `reference` — un Input `number` ou `many` y est refusé.

## Produced fields

```gherkin fragment
    And Produced fields
      | field              | type      | cardinality | domain                      |
      | verifiedRevision   | reference | one         | any                         |
      | verificationStatus | string    | one         | enum "successful", "failed" |
```

- Requis, une fois, au moins une ligne. L'en-tête est exactement `| field | type | cardinality | domain |`.
- `domain` vaut `any`, ou — pour les champs `string` seulement — une énumération écrite exactement `enum "a", "b"` (virgule et une espace ; valeurs non vides et distinctes).
- La projection doit renvoyer **exactement** cet ensemble de champs : mêmes noms, rien de manquant, rien en trop. Les valeurs sont validées contre le type et l'énumération quand l'Opération s'exécute (et quand vous la simulez).
- Ces champs sont les Facts qu'un Check qualifie. Son DocString `js` les lit par `fact`, par exemple `fact.verificationStatus === "successful" || fail("the build failed")`. Une matérialisation en nomme un aussi : `and materializes "fix revision" from field "verifiedRevision"`.

Dans l'éditeur Source, la projection JSONata est un langage embarqué plutôt que du simple texte Gherkin. Elle reçoit une coloration JSONata et le serveur de langage TRUST complète `steps.`, `input.` et `environment.` à partir de l'Opération en cours d'édition. Le même compilateur d'Opération signale les erreurs JSONata et de projection avant publication.

<Callout kind="note" title="Ce qu'atteste un champ produit">
  Un champ copié depuis `input` (par exemple `"verifiedRevision": input.revision`) atteste le **contexte admis** avec lequel l'action s'est exécutée — il n'affirme pas que le système externe a ré-observé cette valeur. Un champ dérivé d'un résultat d'étape atteste le **résultat de l'action** lui-même.
</Callout>

## Credentials

Un token ou un mot de passe de base de données est un <Term id="credential">credential</Term>. L'Opération le déclare par son **nom** et le référence depuis l'étape qui l'utilise. La valeur est stockée pour l'Environnement et n'apparaît jamais dans la source.

```gherkin fragment title="Déclarer les noms"
    And Credentials
      | name          |
      | registryToken |
      | dbPassword    |
      | deployToken   |
```

- Optionnelle, au plus une fois. L'en-tête est exactement `| name |`, au moins une ligne.
- Un nom commence par une lettre et n'utilise que lettres, chiffres ou tirets bas. C'est le nom d'un credential stocké pour l'Environnement.
- Chaque nom déclaré doit être référencé par au moins une étape. Chaque nom référencé doit être déclaré.

Un credential est référencé à exactement trois endroits :

| Étape | Clause | Ce que reçoit l'étape |
| --- | --- | --- |
| HTTP | `with header "<Header>" from Credential "<name>"` | la valeur du header ; jamais une valeur de chemin, de query ou de corps |
| PostgreSQL | `authenticated by Credential "<name>"` | le mot de passe de connexion |
| Shell | `with variable "<VARIABLE>" from Credential "<name>"` | une variable de processus, pour cette étape seulement ; répéter la clause pour plusieurs variables |

```gherkin operation title="Trois étapes, trois références de credential"
# language: en
@trust-dsl:1 @operation:release.publish @version:1.0.0
Feature: Publish one release with Environment credentials

  Background: Operation interface
    Given Environment
      | name          | type      |
      | registryUrl   | url       |
      | databaseUrl   | string    |
      | workspaceRoot | directory |
    And Credentials
      | name          |
      | registryToken |
      | dbPassword    |
      | deployToken   |
    And Input
      | input   | type      | cardinality |
      | project | reference | one         |
    And Produced fields
      | field      | type   | cardinality | domain |
      | registry   | number | one         | any    |
      | releases   | number | one         | any    |
      | deployExit | number | one         | any    |

  Scenario: Run
    When HTTP "registry" sends "GET" to Environment "registryUrl" appending Input "project"
        with header "Authorization" from Credential "registryToken" and reads JSON
    And PostgreSQL "releases" executes SQL on Environment "databaseUrl"
        authenticated by Credential "dbPassword" with Input as JSONB parameter $1
      """
      SELECT count(*)::int AS result FROM releases WHERE project = $1::jsonb->>'project'
      """
    And Shell "deploy" runs "./deploy.sh" with cwd from Environment "workspaceRoot" and Input "project"
        with variable "DEPLOY_TOKEN" from Credential "deployToken"
      | argument |
      | publish  |
    Then Produce with JSONata
      """
      {
        "registry": steps.registry.status,
        "releases": steps.releases.result,
        "deployExit": steps.deploy.exitCode
      }
      """
```

Ce qui se passe à l'exécution :

- **Admission.** Sur un Plan en direct, TRUST résout exactement les noms déclarés parmi les credentials de l'Environnement du Plan. Un credential non déclaré n'est jamais délégué. Un credential déclaré absent de l'Environnement refuse la tentative, raison `credential-missing`, avant toute action externe.
- **Dry-run.** Un dry-run n'exécute rien d'externe et ne reçoit aucun credential.
- **Étapes.** Le Runner ne donne chaque valeur qu'à l'étape qui la référence. `Produce with JSONata` et un corps de requête JSONata ne peuvent pas lire les credentials : la racine `credentials` est refusée à la compilation.
- **Masquage.** Le Runner remplace chaque valeur déléguée par `[credential <name>]` dans les résultats d'étape, le résultat de l'action, les messages d'erreur et les diagnostics avant qu'ils ne quittent l'étape. Les Facts, les résultats du Runner et les traces ne portent jamais la valeur d'un credential.

<Callout kind="rule">
  Une Opération nomme les credentials dont elle a besoin. L'Environnement détient leurs valeurs. Seule une tentative en direct admise les reçoit, et seules les étapes qui les référencent les utilisent.
</Callout>

<Details title="Forme compilée des credentials" expert>
L'Opération compilée liste les noms déclarés dans `credentials` (absent quand aucun n'est déclaré). Chaque référence se compile en une source `{ "kind": "credential", "credential": "<name>" }` : sur le header HTTP, sur l'`authentication` PostgreSQL ou sur l'entrée `variables` du Shell. La compilation refuse une référence non déclarée (`unknown-credential`), un nom répété (`duplicate-credential`), un nom déclaré qu'aucune étape ne référence, et une projection qui lit `credentials` (`credential-projection`). À l'admission, l'accord porte les valeurs résolues dans une carte `credentials` indexée par nom, distincte de la carte `environment`. Un accord de dry-run porte une carte vide.
</Details>

## Pas de secrets dans la source

Les headers HTTP sont structurés, mais la source de l'Opération et les `string` lisibles d'Environment ne stockent pas de secrets. Le compilateur refuse une valeur ressemblant à un secret (clé `sk-…`, token `gh…_`, valeur `Bearer …`) — code `secret-like-value` — et le Runner refuse les URL avec credentials embarqués. Un secret est un credential d'Environnement, déclaré dans `Credentials` et référencé par son nom. Voir [Environnements](/docs/environments#credentials) pour sa définition par un opérateur.

<Details title="Forme compilée de l'interface" expert>
Le compilateur émet trois JSON Schemas fermés. La correspondance Environment est `directory → trust-directory`, `url → trust-url`, `string → trust-string` ; chaque valeur déclarée est requise. Les correspondances Input et Produced sont inchangées ; `many` enveloppe le schéma de l'élément et un domaine enum ajoute `enum: [...]`.
</Details>
