```gherkin fragment
    Then Produce with JSONata
      """
      {
        "headRevision": $trim(steps.head.stdout),
        "workingTree": $trim(steps.status.stdout) = "" ? "clean" : "dirty"
      }
      """
```

La projection est une expression <Term id="jsonata">JSONata</Term> dans une doc string. Elle est évaluée une fois, après la dernière étape, et doit renvoyer **un objet avec exactement les champs produits déclarés**. Le Runner l'évalue après une exécution réelle ; **Simuler** l'évalue sur des résultats d'étapes que vous saisissez ; le compilateur la vérifie statiquement dans les deux cas.

> La projection est vérifiée avant que quoi que ce soit s'exécute : étape inconnue, champ inconnu, fonction interdite — l'Opération ne compile pas.

## Ce que voit l'expression

Quatre racines, et rien d'autre :

| Racine | Contenu | Profondeur |
| --- | --- | --- |
| `input.<name>` | les valeurs d'Input validées | un niveau (`input.project` ; `input.a.b` est refusé) |
| `environment.<name>` | les valeurs d'Environment | un niveau |
| `steps.<stepName>.<result>` | le résultat de l'étape de ce nom | voir ci-dessous |
| `execution.id` | l'identifiant stable de cette exécution d'Opération admise | exactement `id` |

Résultats d'étapes, par sorte d'étape :

| Étape | Clés | Traversable |
| --- | --- | --- |
| Shell | `exitCode`, `stdout`, `stderr` | non — `steps.head.stdout` est une chaîne entière |
| File `as Text` | `relativePath`, `content` | non |
| File `as JSON` | `relativePath`, `content` | `content` oui — `steps.manifest.content.name` |
| HTTP `as Text` | `status`, `headers`, `body` | non |
| HTTP `and reads JSON` (toute méthode) | `status`, `headers`, `body` | `body` oui — `steps.issue.body.summary` |

Les étapes sont désignées **par nom**, jamais par position.

## Le sous-ensemble fermé

Le compilateur accepte les littéraux, les clés d'objet fixes, les conditionnelles, le groupement et la
surface de référence générée suivante :

<OperationLanguageReference />

Refusé : les fonctions absentes de cette table (dont `$now` et `$eval`), les lambdas, la chaîne `~>`,
les expressions régulières, les opérateurs de transformation, les jokers et descendants, les
constructeurs de tableau `[…]`, le moins unaire, les sélecteurs d'index (`items[0]`) et la liaison de
variables. Les filtres fixes tels que `items[status = "ok"]` sont acceptés ; leurs chemins restent
soumis au même sous-ensemble fermé.

<Callout kind="note" title="Pourquoi un sous-ensemble">
  La projection fait partie de ce qui rend un Fact digne de confiance : elle doit faire la même chose sur le Runner et dans Simuler, terminer, et être lisible en revue. Le calcul qui n'y tient pas appartient au système externe (un script, un endpoint) dont l'Opération lit ensuite le résultat.
</Callout>

## Formes typiques

```jsonata title="Copier un Input, nettoyer une sortie Shell"
{ "verifiedProject": input.project, "verifiedRevision": $trim(steps.head.stdout) }
```

```jsonata title="Code de sortie vers un statut énuméré"
{ "verificationStatus": steps.verify.exitCode = 0 ? "successful" : "failed" }
```

```jsonata title="Sortie vide vers un statut"
{ "workingTree": $trim(steps.status.stdout) = "" ? "clean" : "dirty" }
```

```jsonata title="Nombre depuis du texte, concaténation"
{ "commitsAhead": $number($trim(steps.commits.stdout)), "containerImage": input.containerName & "=" & input.image }
```

```jsonata title="Champs d'une réponse JSON"
{ "service": steps.response.body.service, "status": steps.response.status }
```

## Ce qui est vérifié

À la compilation :
- la syntaxe ; chaque racine, nom d'étape et clé de résultat existe ; les règles de profondeur ;
- le nœud du sommet est un littéral d'objet avec des clés fixes ;
- l'ensemble des clés est égal à l'ensemble des `Produced fields` — rien de manquant, rien en trop (`Produce fields must be exactly: a, b, c`).

À l'exécution (Runner et Simuler) : les valeurs renvoyées sont validées contre les types et énumérations des champs produits. Un `buildStatus` hors de `enum "successful", "failed"` est une erreur de validation, et l'Opération ne produit aucun Fact.

<Details title="Diagnostics de la projection" expert>
| Message | Cause |
| --- | --- |
| `Produce with JSONata is invalid: …` | erreur de syntaxe JSONata |
| `Produce uses unsupported JSONata form "…"` / `… function "$…"` / `… operator "…"` / `… unary operator` | hors du sous-ensemble |
| `Produce allows only fixed JSONata filter path stages` | un sélecteur d'index ou une autre étape de chemin dynamique |
| `Produce with JSONata must return one object literal` · `… must use fixed field names` | mauvais nœud de sommet |
| `Produce fields must be exactly: …` | l'ensemble des clés diffère des champs produits |
| `Produce references unknown root "…"` / `unknown Operation step "…"` / `unknown <kind> result "…"` / `unknown Input field "…"` / `unknown Environment field "…"` | le nom n'existe pas |
| `Produce cannot traverse Shell result "…"` / `Text File content` / `File relativePath` / `HTTP result "…"` / `Text HTTP body` / `Input field "…"` / `Environment field "…"` | le chemin descend sous une valeur opaque |
| `Produce with JSONata cannot be empty` · `… must use Then and one DocString` · `… must be the final step` · `Operation repeats Produce with JSONata` | forme et position |
</Details>
