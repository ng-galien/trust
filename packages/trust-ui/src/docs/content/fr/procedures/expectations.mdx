title: "Qualifications"
summary: "Des expressions JavaScript fermées qui transforment les Facts produits par un Check en verdict et en raison exploitable."
order: 4
---

Chaque Check porte un DocString `js`. Son expression de forme JavaScript énonce la qualification et
la raison renvoyée en cas d'échec. TRUST analyse et type cette source, la compile en JSON Logic, puis
évalue les règles compilées ; il n'exécute jamais de JavaScript.

```gherkin fragment
    Then Check "fix" runs Operation "git.head-compare"
        on "project" as Input "project"
        using "baseline revision" as Input "baseRevision"
        and must establish "the fix is committed after the baseline"
      """js
      (
        fact.comparedBaseRevision === context["baseline revision"] ||
        fail(`Expected baseline ${context["baseline revision"]}, observed ${fact.comparedBaseRevision}`)
      ) && (
        fact.commitsAhead >= 1 ||
        fail(`The fix has ${fact.commitsAhead} commits after the baseline`)
      )
      """
```

## Forme d'une garde

Une garde a exactement la forme `booleanExpression || fail(stringExpression)`. Plusieurs gardes se
joignent avec `&&` ; TRUST les évalue dans l'ordre de la source et renvoie la raison calculée de la
première garde en échec. Si toutes réussissent, le Check est validé avec sa raison `must establish`.

L'expression ne voit que trois racines en lecture seule :

| Racine | Contenu |
| --- | --- |
| `fact` | toutes les valeurs Produced acceptées pour le Check courant |
| `context` | les rôles visibles du Plan, indexés par leur nom de rôle |
| `checks` | les valeurs Produced des Checks prérequis explicitement référencés |

Utilisez le point pour un identifiant JavaScript (`fact.status`) et les crochets pour un nom en
langage naturel (`context["fix revision"]`, `checks["opening check"].openedAt`). Les noms et les types
sont résolus lors de la compilation de la Procédure.

## Surface d'expression fermée

L'expression admet les littéraux, tableaux, parenthèses, chaînes template, ternaires et la surface de
référence générée ci-dessous. Les callbacks de collection ne contiennent qu'une expression. Les
instants utilisent les opérateurs d'ordre ordinaires après normalisation de leurs valeurs typées par TRUST.

<ProcedureLanguageReference />

Les affectations, instructions, boucles, déclarations, constructions d'objet, propriétés dynamiques,
fonctions arbitraires, modules, API hôtes et mutations sont refusés. Chaque condition est statiquement
booléenne et chaque raison de `fail` statiquement textuelle.

## Cycle de qualification

1. Le Runner, ou l'opérateur en dry-run, rapporte les valeurs Produced de l'Opération.
2. Le lot complet de Facts est validé contre le Product Action Contract avant persistance.
3. TRUST injecte uniquement les références compilées et évalue la condition de chaque garde dans l'ordre.
4. La première condition fausse évalue sa raison et renvoie **non validé** ; si toutes sont vraies,
   TRUST renvoie **validé** avec la raison de succès du Check.
5. Le verdict remplace la qualification active et les Checks dépendants sont rouverts.

<Callout kind="note" title="Formulation des raisons">
  Les raisons sont lues par l'agent et affichées dans l'historique. Utilisez les valeurs qui expliquent
  l'observation, de préférence dans une chaîne template, plutôt qu'une instruction adressée à l'agent.
</Callout>

<Details title="Qualification compilée" expert>
Le compilateur conserve la source pour l'affichage et émet des gardes ordonnées contenant
`conditionLogic`, `failureReasonLogic` et les références typées résolues. Le runtime dépend uniquement
de ces règles JSON Logic canoniques.
</Details>
