Every Check carries one `js` DocString. Its JavaScript-shaped expression states the qualification and
the reason returned when it fails. TRUST parses and types this source, compiles it to JSON Logic, then
evaluates the compiled rules; it never executes JavaScript.

```gherkin fragment
    Then Check "fix" runs Operation "git.head-compare"
        on "project" as Input "project"
        using "baseline revision" as Input "baseRevision"
        and must establish "the fix is committed after the baseline"
      """js
      (
        fact.comparedBaseRevision === context["baseline revision"] ||
        fail(`Expected baseline ${context["baseline revision"]}, observed ${fact.comparedBaseRevision}`)
      ) && (
        fact.commitsAhead >= 1 ||
        fail(`The fix has ${fact.commitsAhead} commits after the baseline`)
      )
      """
```

## Guard form

One guard has the exact shape `booleanExpression || fail(stringExpression)`. Several guards join with
`&&`; TRUST evaluates them in source order and returns the first failed guard's computed reason. When
all guards hold, the Check is validated with its `must establish` reason.

The expression sees three read-only roots:

| Root | Content |
| --- | --- |
| `fact` | every Produced value accepted for the current Check |
| `context` | the visible Plan roles, keyed by their role names |
| `checks` | Produced values of explicitly referenced prerequisite Checks |

Use dot access for a JavaScript identifier (`fact.status`) and bracket access for a natural-language
name (`context["fix revision"]`, `checks["opening check"].openedAt`). Names and types are resolved when
the Procedure compiles.

## Closed expression surface

The expression admits literals, arrays, parentheses, template strings, ternaries and the generated
reference surface below. Collection callbacks contain expressions only. Instants use ordinary ordered
operators after TRUST normalizes their typed values.

<ProcedureLanguageReference />

Assignments, statements, loops, declarations, object construction, dynamic properties, arbitrary
functions, modules, host APIs and mutation are rejected. Every condition is statically boolean and
every `fail` reason statically string.

## Qualification lifecycle

1. The Runner, or the operator in a dry-run, reports the Operation's Produced values.
2. The complete Fact batch is validated against the Product Action Contract before it is persisted.
3. TRUST injects only the compiled references and evaluates each guard's condition in order.
4. The first false condition evaluates its reason and returns **not validated**; all true conditions
   return **validated** with the Check's success reason.
5. The verdict replaces the active qualification and dependent Checks reopen.

<Callout kind="note" title="Reason wording">
  Reasons are read by the agent and shown in history. Use the values that explain the observation,
  preferably through a template string, rather than an instruction to the agent.
</Callout>
