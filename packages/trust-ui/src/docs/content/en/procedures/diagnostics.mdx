The compiler returns a compiled Procedure or **one diagnostic**: a code, a message and a location (the physical line, continuation lines included). The interface shows it in the status line and underlines the line in the source editor; publication returns the same diagnostic when the runtime compiles the source.

> A source that does not compile cannot be published; a published version compiled once and never changes.

## Codes

| Code | Meaning |
| --- | --- |
| `invalid-procedure` | the document shape, a tag, a sentence, a table or a clause breaks the closed grammar |
| `invalid-identifier` | the Procedure slug, the version or a Scenario slug has the wrong form |
| `unknown-operation` | a Check runs an Operation that is not in the catalog |
| `unknown-role` · `unknown-input` · `unknown-field` | a name does not exist: a role, an Operation Input, a produced field |
| `duplicate-role` · `duplicate-check` · `duplicate-scenario` | a name is declared twice |
| `input-unbound` | an Input is bound twice or not at all |
| `incompatible-type` · `incompatible-cardinality` | a binding, materialization or expectation does not match the shapes |
| `invalid-dependency` | a prerequisite, referenced Check or materialized role is misplaced or unknown |
| `dependency-cycle` | a cycle among Scenarios or role parents |

## Messages by cause

### Identity and shape
- `Procedure is not valid Gherkin: …` · `Procedure must contain one English Feature`.
- `procedure tag must appear exactly once` / `version tag …` / `TRUST DSL tag …` / `Scenario tag …` · `… tag cannot be empty` · `Unknown tag "…"`.
- `Procedure "…" must be a lowercase slug` · `Version "…" must be semantic` · `Scenario "…" must be a lowercase slug` · `TRUST DSL "…" is unsupported`.
- `Rules are outside the closed Procedure grammar` · `Scenario Outline is outside the closed Procedure grammar`.
- `Procedure must declare exactly one Background named Plan context` · `Procedure must declare at least one Scenario`.

### Plan context
- `Plan context accepts only role sentences` — a keyword other than `Given`/`And`, a table, a doc string.
- `Role "…" is repeated` · `Role "…" has unknown parent "…"` · `Role parent cycle contains "…"`.
- `Role "…" cannot be declared and fixed` · `Fixed role "…" must have cardinality one` · `Fixed role "…" must be a string or reference`.
- Sentence errors: `Invalid sentence "…"` · `Expected one of: one, many` · `Expected a quoted value` · `Sentence has trailing words`.

### Scenarios
- `Scenario "…" is repeated` · `Scenario "…" must contain Checks and its aggregation`.
- `Scenario dependencies must precede Checks` · `Scenario "…" depends on unknown Scenario "…"` · `Scenario "…" depends on itself` · `Scenario dependency cycle contains "…"`.
- `Check placement is invalid` — a Check with another keyword than `Then`/`And`, or after the closing sentence.
- `Scenario aggregation is invalid` — the closing sentence with another keyword, a table, or twice.

### Check sentence and bindings
- `Check "…" is repeated` · `Check "…" must establish one reason` · `Check "…" has trailing words`.
- `Check "…" references unknown Operation "…"` · `Check "…" references unknown role "…"` · `Operation "…" has no Input "…"`.
- `Check "…" binds Input "…" more than once` · `Check "…" does not bind Input: a, b`.
- `Check "…" cannot run on each member of one role "…"` · `Check "…" cannot select all values of one role "…"` · `Check "…" cannot select one unscoped value of role "…"`.
- `Input "…" and role "…" have incompatible cardinality` · `Input "…" and role "…" have incompatible types`.

### Materialization
- `Check "…" materializes unknown role "…"` · `Check "…" cannot materialize declared or fixed role "…"` · `Role "…" has more than one provider`.
- `Operation "…" produces no field "…"` · `materialization of role "…" does not match role type and cardinality`.
- `Check "…" uses role "…" before its provider Scenario is validated` · `Check "…" compares with role "…" before its provider Scenario is validated`.

### Expectations
- `Every Check requires a predicate table` · `Check table must use: field | relation | expectation | failure reason` · `Check predicate row must contain four cells` · `Failure reason cannot be empty`.
- `Relation "…" is unknown` · `Number expectation "…" is invalid` · `Expected one of: value, number, valid, context, field`.
- `Operation "…" produces no field "…"` · `Expectation references unknown role "…"` · `Expectation references unknown Check "…"` · `Check "…" produces no field "…"` · `Check "…" is not in a prerequisite Scenario`.
- `Field "…" is not a number` · `Field "…" is not an instant` · `Field "…" cannot be compared with a string value` · `Value "…" is outside field "…" domain`.
- `expectation for field "…" does not match role type and cardinality` · `field "…" and upstream field "…" have incompatible types`.
- `equals requires the same type and cardinality` · `valid rfc3339 requires one instant field` · `at least requires one number field and one number expectation` · `has at least requires a collection field and one number expectation` · `is in requires one field and a collection expectation of the same type` · `before requires one instant field and one instant expectation` (`after` likewise).

<Callout kind="tip">
  The most frequent causes: a `Given scenario … is validated` written after a Check; a role used in the same Scenario that materializes it; a `many` role bound without `each` or `all`; a `value "…"` outside the field's enumeration; a forgotten closing sentence; a Check name reused.
</Callout>
