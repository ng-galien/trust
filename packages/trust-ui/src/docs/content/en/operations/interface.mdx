The `Background` of an Operation is its contract: what a Procedure binds (Input), what an <Term id="environment">Environment</Term> provides (Environment), what a Check can test (Produced fields). Everything is typed, named in lower camel case and closed — no optional value, no free-form key. An optional fourth table, `Credentials`, names the secrets of the Environment that its steps use.

> Input comes from the Check, Environment from the execution context, Produced fields go to the Check.

```gherkin fragment title="The three declarations"
  Background: Operation interface
    Given Environment
      | name          | type      |
      | workspaceRoot | directory |
    And Input
      | input   | type      | cardinality |
      | project | reference | one         |
    And Produced fields
      | field        | type      | cardinality | domain                |
      | headRevision | reference | one         | any                   |
      | workingTree  | string    | one         | enum "clean", "dirty" |
```

## Value types

The same four types serve Input and Produced fields; Environment has three execution value types.

| Type | Meaning | Validated as |
| --- | --- | --- |
| `string` | free text | a JSON string |
| `number` | a number | a JSON number |
| `instant` | a point in time | an RFC 3339 date-time string |
| `reference` | an identifier of something outside TRUST (a revision, an issue key, a project name) | a non-empty string |
| `directory` *(Environment only)* | the place where projects live | an absolute filesystem path |
| `url` *(Environment only)* | the base URL of a service | an `http(s)` URL without embedded credentials |
| `string` *(Environment only)* | a non-secret request or execution setting | a non-empty string without NUL |

**Cardinality** is `one` (a scalar) or `many` (an array of the type). There is no optional value: every declared Input and Environment value is required, and the Operation must produce every declared field.

## Environment

```gherkin fragment
    Given Environment
      | name          | type      |
      | workspaceRoot | directory |
      | serviceUrl    | url       |
      | apiMode       | string    |
```

- Required, once, at least one row. The header is exactly `| name | type |`.
- A `directory` names **the place where all projects live**, not one project. A Shell or File step narrows it to one project with `and Input "<name>"`: the Input must be one string naming a directory directly below the root — no path separator, no `..`, no symbolic link out of the root. Without that clause the step runs in the directory itself.
- A `url` is the base of any HTTP method; structured clauses may append encoded path segments and query parameters.
- A `string` supplies non-secret HTTP query, header or Text body values.
- The values come from the Environment chosen at admission (live) or from the current Environment of the interface (**Run** tab). An Operation is *runnable* on an Environment when the Environment declares every name it needs — that is what the ✓ marks of the catalog and of the Environment screen show.

## Input

```gherkin fragment
    And Input
      | input        | type      | cardinality |
      | project      | reference | one         |
      | baseRevision | reference | one         |
      | documents    | reference | many        |
```

- Optional (an Operation may need no Input), at most once. The header is exactly `| input | type | cardinality |`.
- Where the values come from: in a Plan, the Check sentence binds each Input to a Plan context role (`on "project" as Input "project"`, `using "baseline" as Input "baseRevision"`). Every Input must be bound exactly once. In the interface, **Simulate** and **Run** ask you for them.
- What an Input may feed: a Shell argument, directory narrowing, an HTTP path/query/header/Text body value, the complete JSON request body, a JSONata request body, and the `input.<name>` root of Produce.
- Wherever a step needs **one string**, the Input must be cardinality `one` and of type `string`, `instant` or `reference` — a `number` or a `many` Input is refused there.

## Produced fields

```gherkin fragment
    And Produced fields
      | field              | type      | cardinality | domain                      |
      | verifiedRevision   | reference | one         | any                         |
      | verificationStatus | string    | one         | enum "successful", "failed" |
```

- Required, once, at least one row. The header is exactly `| field | type | cardinality | domain |`.
- `domain` is `any`, or — for `string` fields only — an enumeration written exactly `enum "a", "b"` (comma and one space; values non-empty and distinct).
- The projection must return **exactly** this set of fields: same names, nothing missing, nothing extra. Values are validated against the type and the enumeration when the Operation runs (and when you simulate it).
- These fields are the Facts a Check qualifies. Its `js` DocString reads them through `fact`, for example `fact.verificationStatus === "successful" || fail("the build failed")`. A materialization also names one: `and materializes "fix revision" from field "verifiedRevision"`.

In the Source editor, the JSONata projection is an embedded language rather than plain Gherkin text. It has JSONata syntax highlighting and the TRUST language server completes `steps.`, `input.` and `environment.` from the Operation being edited. The same Operation compiler reports invalid JSONata and projection errors before publication.

<Callout kind="note" title="What a produced field attests">
  A field copied from `input` (for example `"verifiedRevision": input.revision`) attests the **admitted context** the action ran with — it does not claim the external system re-observed that value. A field derived from a step result attests the **action result** itself.
</Callout>

## Credentials

A token or a database password is a <Term id="credential">credential</Term>. The Operation declares it by **name** and references it from the step that uses it. The value is stored for the Environment and never appears in the source.

```gherkin fragment title="Declare the names"
    And Credentials
      | name          |
      | registryToken |
      | dbPassword    |
      | deployToken   |
```

- Optional, at most once. The header is exactly `| name |`, at least one row.
- A name starts with a letter and uses letters, digits or underscores. It is the name of a credential stored for the Environment.
- Every declared name must be referenced by at least one step. Every referenced name must be declared.

A credential is referenced in exactly three places:

| Step | Clause | What the step receives |
| --- | --- | --- |
| HTTP | `with header "<Header>" from Credential "<name>"` | the header value; never a path, query or body value |
| PostgreSQL | `authenticated by Credential "<name>"` | the connection password |
| Shell | `with variable "<VARIABLE>" from Credential "<name>"` | one process variable, for this step only; repeat the clause for several variables |

```gherkin operation title="Three steps, three credential references"
# language: en
@trust-dsl:1 @operation:release.publish @version:1.0.0
Feature: Publish one release with Environment credentials

  Background: Operation interface
    Given Environment
      | name          | type      |
      | registryUrl   | url       |
      | databaseUrl   | string    |
      | workspaceRoot | directory |
    And Credentials
      | name          |
      | registryToken |
      | dbPassword    |
      | deployToken   |
    And Input
      | input   | type      | cardinality |
      | project | reference | one         |
    And Produced fields
      | field      | type   | cardinality | domain |
      | registry   | number | one         | any    |
      | releases   | number | one         | any    |
      | deployExit | number | one         | any    |

  Scenario: Run
    When HTTP "registry" sends "GET" to Environment "registryUrl" appending Input "project"
        with header "Authorization" from Credential "registryToken" and reads JSON
    And PostgreSQL "releases" executes SQL on Environment "databaseUrl"
        authenticated by Credential "dbPassword" with Input as JSONB parameter $1
      """
      SELECT count(*)::int AS result FROM releases WHERE project = $1::jsonb->>'project'
      """
    And Shell "deploy" runs "./deploy.sh" with cwd from Environment "workspaceRoot" and Input "project"
        with variable "DEPLOY_TOKEN" from Credential "deployToken"
      | argument |
      | publish  |
    Then Produce with JSONata
      """
      {
        "registry": steps.registry.status,
        "releases": steps.releases.result,
        "deployExit": steps.deploy.exitCode
      }
      """
```

What happens at execution:

- **Admission.** On a live Plan, TRUST resolves exactly the declared names from the credentials of the Plan's Environment. A credential that is not declared is never delegated. A declared credential missing from the Environment refuses the attempt, reason `credential-missing`, before any external action.
- **Dry-run.** A dry-run executes nothing external and receives no credential.
- **Steps.** The Runner gives each value only to the step that references it. `Produce with JSONata` and a JSONata request body cannot read credentials: the `credentials` root is refused at compilation.
- **Masking.** The Runner replaces every delegated value with `[credential <name>]` in step results, the action outcome, error messages and diagnostics before they leave the step. Facts, Runner results and traces never carry a credential value.

<Callout kind="rule">
  An Operation names the credentials it needs. The Environment holds their values. Only an admitted live attempt receives them, and only the steps that reference them use them.
</Callout>

<Details title="Compiled form of credentials" expert>
The compiled Operation lists the declared names in `credentials` (absent when none are declared). Each reference compiles to a `{ "kind": "credential", "credential": "<name>" }` source: on the HTTP header, on the PostgreSQL `authentication`, or on the Shell `variables` entry. Compilation refuses an undeclared reference (`unknown-credential`), a repeated name (`duplicate-credential`), a declared name that no step references, and a projection that reads `credentials` (`credential-projection`). At admission, the grant carries the resolved values in a `credentials` map keyed by name, separate from the `environment` map. A dry-run grant carries an empty map.
</Details>

## No secrets in the source

HTTP headers are structured, but Operation source and readable Environment strings are not secret storage. The compiler refuses a secret-like value (an `sk-…` key, a `gh…_` token, a `Bearer …` value) — code `secret-like-value` — and the Runner refuses URLs with embedded credentials. A secret is an Environment credential, declared in `Credentials` and referenced by name. See [Environments](/docs/environments#credentials) for how an operator defines it.

<Details title="Compiled form of the interface" expert>
The compiler emits three closed JSON Schemas. Environment mapping is `directory → trust-directory`, `url → trust-url`, `string → trust-string`; every declared Environment value is required. Input and Produced mappings are unchanged; `many` wraps the item schema in an array and an enum domain adds `enum: [...]`.
</Details>
