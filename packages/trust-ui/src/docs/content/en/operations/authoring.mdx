The **Operations** entry of the sidebar opens the catalog. Selecting an Operation opens its page over the catalog; the tab and the selection are in the URL, so a page can be shared and reopened as it was.

### Overview

The Operation in words: its description, what it needs, what it does step by step, what it produces. In expert mode two more blocks open: the contract of each step (executable and arguments, path, URL, accepted exits) and the projection.

### Source

<Screenshot id="operation-source" caption="Source tab: the editor with live compilation." legend={{
  "editor": "The Gherkin source. Compiled on every change; a diagnostic underlines its line and is repeated in the status line.",
  "editor.format": "Format source: re-flows long steps onto continuation lines (also Shift+Alt+F).",
  "overlay.status": "Compiles / does not compile, with the message and the line.",
}} />

- The editor knows the language: colouring, folding, completions for every sentence and table (⌃Space), and the **Operation feature** template.
- Visual word wrap changes the display only. **Format source** changes the text by placing long steps onto continuation lines; these are distinct controls.
- Editing creates a draft with an explicit modification indicator. **Discard changes** restores the selected published source; it never deletes a publication.
- **Publish** writes a new immutable version as `<operation>@<version>.feature`. It is enabled only for a compiled draft whose identity and version are not already published. Change the version before publishing an evolution; previous versions remain available.

### Simulate

<Screenshot id="operation-simulate" caption="Simulate tab: step results typed by hand, projection evaluated for real." legend={{
  "simulation.input": "The Input values, one field per declared Input, validated as you type.",
  "simulation.steps": "One block per step, with the fields of its result shape (exit code and outputs, file content, HTTP status and body).",
  "simulation.run": "Run simulation — enabled when every required field is filled.",
  "simulation.result": "The produced fields, typed, and the raw JSON.",
}} />

Simulate **executes nothing**: it evaluates the projection of the current source on the step results you provide, and validates the result against the produced fields. Use it to check a projection before running, or to see what an Operation would produce in a case that is hard to reproduce (a failing build, a 404). Expert mode adds a JSON view of the whole simulation input.

### Run

<Screenshot id="operation-run" caption="Run tab: one execution on the current Environment." legend={{
  "run.environment": "The Environment of the run: the current one when it declares every needed value, otherwise a compatible one to pick — with the values it provides.",
  "run.input": "The Input, one field per declared Input.",
  "run.start": "Run for real: the runtime executes the Operation with its Runner and streams the progress. Stop cancels a running one.",
  "run.recent": "Recent runs of this Operation, with their state.",
  "run.report": "The report of the selected run: each step with its outcome and output, then the produced values.",
}} />

Run executes the Operation on the chosen Environment **outside any Plan**: no Check, no Facts, no verdict — a way to try an Operation against a real system. The report shows each step (command or request, exit or status, output) and the produced fields, or the point where the Operation was interrupted. An unsaved source can be run; the page warns before starting.

<Callout kind="note" title="Runnable, or not">
  An Operation is runnable on an Environment when the Environment declares every value of its `Environment` table. When the current Environment does not, the Run tab says which values are missing and links to that Environment; the catalog and the Environment screen show the same information as ✓ / ✗ marks.
</Callout>

### Contract JSON (expert)

The compiled Operation: identity, schemas of the interface, steps, projection, classification. It is what a Procedure embeds and what the Runner receives.

## Creating, duplicating, publishing

<Steps>
  <Step title="New operation">From the catalog header or the sidebar. The Source tab opens on a template; the status line shows the first diagnostic until the source compiles.</Step>
  <Step title="Duplicate">Opens a draft pre-filled with the current source; choose a new identity or version before publication.</Step>
  <Step title="Publish">Stores a compiled draft under a new immutable version; the catalog reloads and the page opens that version.</Step>
  <Step title="Discard changes">Restores the selected published source when a draft has changed. Published versions cannot be deleted, even when unused.</Step>
</Steps>

## Agent access

The runtime MCP exposes text-oriented tools to list and read the catalog, compile, publish through `trust_operation_save`, simulate, discover compatible Environments, then start, list, read or cancel a Trial. The discoverable remove tool refuses published versions. Draft source can be simulated or run without publishing it. The MCP adapter calls the same catalog, compiler, projection and Trial services as the interface; it does not relay RPC responses or expose their DTOs.
