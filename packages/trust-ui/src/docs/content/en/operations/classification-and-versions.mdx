```gherkin fragment
# language: en
@trust-dsl:1 @operation:git.head-read @version:1.0.0 @x-family:software-delivery @x-nature:observe
Feature: Read Git HEAD and working tree

  Reads the current revision and whether the working tree is clean.
```

## Identity tags

| Tag | Rule |
| --- | --- |
| `@operation:<domain>.<action>` | exactly one. Two lower-case segments separated by one dot; each segment is alphanumeric with optional hyphens (`git.head-compare`, `docker.image-build`). The domain groups the catalog; the action names what is done |
| `@version:<major>.<minor>.<patch>` | exactly one, a valid SemVer version; prerelease and build metadata follow SemVer rules |
| `@trust-dsl:1` | exactly one, value `1` — the version of the language |
| anything else | must be an `@x-` classification tag; otherwise `Tag "…" is outside the closed Operation grammar` |

Tag order is free. The catalog writes `@trust-dsl:1 @operation:… @version:…`.

## Classification `@x-<key>:<value>`

Free, repeatable, opaque to execution: `@x-family:software-delivery`, `@x-nature:observe`, `@x-team:platform @x-team:sre`. The key starts with a lower-case letter (hyphenated segments allowed); the value has no space and no colon. The compiler groups them by key (`classification: { family: ["software-delivery"], nature: ["observe"], team: ["platform", "sre"] }`), duplicates removed.

The catalog screen uses `family` and `nature` for its facets; anything else is yours to define.

## Title and description

`Feature: <title>` is the human title, copied verbatim. The free-text block under it is the **description**: what the Operation observes, its assumptions, what an accepted exit means. It is shown on the Operation overview and in the graph of the Procedures that use it. It is never executed. Indentation and repeated blank lines are normalised.

## Versions

- The identity of a catalog entry is `name@version` (`git.head-read@1.0.0`). The catalog is a directory of `.feature` files, one entry per file; the same `name@version` in two files is refused.
- The interface publishes a new Operation version into `<name>@<version>.feature`, preserving earlier versions. An existing identity/version or source file cannot be overwritten. Published versions cannot be deleted; unpublished draft edits can be discarded.
- A Procedure references an Operation or child Procedure with `name@selector`: an exact version or a standard node-semver range such as `^1.2.3` or `~1.2.3`. The highest matching candidate must pass the existing compatibility checks; TRUST does not silently fall back to an older candidate. Tags such as `latest` are not supported.
- A new Plan resolves and pins the complete recursive composition. Later publications do not change its Checks, delayed children, resumed execution or replacement child generations. The catalog groups each identity once; the detail view selects its exact version.
- Runnable marks (✓ on the catalog, on the Environment screen) are computed per catalog entry against the values each Environment declares.

<Callout kind="rule">
  Published versions are immutable. A floating reference can select a newer version for a new Plan, but the composition of an engaged Plan remains fixed.
</Callout>

<Details title="Compiled Operation and digest" expert>
The compiler emits `trust.compiled-operation@1` with: `operation`, `version`, `title`, `description?`, `source` (the normalised Gherkin), `input`, `environment`, `produced` (JSON Schemas), `steps` (ordered, typed), `produce` (`{ language: "jsonata", expression }`) and `classification?`. The **Contract JSON** tab of the interface shows this object.

The Procedure compiler computes a SHA-256 **digest** of the semantics of each embedded Operation: everything above except `source`, with the projection replaced by its abstract syntax tree stripped of positions. Comments, indentation and JSONata formatting therefore do not change the digest; the title, description, classification, interface, steps and the meaning of the projection do.
</Details>
