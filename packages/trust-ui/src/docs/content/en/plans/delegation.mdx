---
title: "Following delegation"
summary: "Read parent and child Plans together with their Checks and recorded results."
order: 3
screen: /delegation
---

Open **Delegation** under **Run** to follow recorded parent–child Plan branches. The number in the heading counts root branches; the subtitle separately counts Plans that have delegated children. The default tree nests every descendant under its recorded parent. Unrelated standalone Plans are excluded. Expand or collapse a branch, or search for a Plan to retain its ancestry. Cards and sorting remain available.

Each root shows its Procedure, Environment and the Environment's `workspaceRoot` value when present. That path identifies the configured workspace, not a canonical project assignment. Follow the Environment link for its configuration. A child inherits neither a project identity nor an agent assignment merely from its place in the tree.

Open a tree item for a single work summary. A direct link to a child still opens the entire branch, with that child selected. The tree uses Procedure identifiers as readable labels; the generated Plan identifier remains available under **Technical Plan ID**. Select a work item in the left-hand list to read its expected result, recorded qualification and prerequisites in the adjacent detail. The parent Plan appears above its indented child Plans. Selecting the parent shows its own verification. The detail reuses the Plan checklist, including scenario hierarchy, expandable Checks, inputs, qualification history, attempts and returned Facts. It links to the Plan execution and, for a published Procedure, its pinned catalog version. An inline Procedure has no catalog publication: its pinned source opens in place. Full work instructions remain in the Plan. On narrow screens, the list appears above the detail. There are no Overview/Work tabs or counter banners. Closing the detail preserves catalog filters.

Host-level agent dispatch is not inferred from Plan names or labels. Coordination information is not part of this runtime projection. Superseded generations remain marked explicitly. Invocations without a child appear in the selected parent's overview when that parent is already part of a recorded delegation.

Check order is a reading order, not a new execution sequence. The runtime owns prerequisites and qualification. This view reads existing Plans and follows their updates; it does not engage Plans, dispatch workers, execute Checks or qualify work.
