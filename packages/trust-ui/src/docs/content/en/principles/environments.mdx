---
title: "Environments and credentials"
summary: "Named execution contexts — directories, URLs, credential references — what an Operation needs, what a Plan is engaged on, what the interface calls current."
order: 4
---

- An <Term id="environment">Environment</Term> is a named set of values: **directories** (where projects live) and **URLs** (base addresses of services), plus references to **credentials**.
- An Operation declares the values it needs (its `Environment` table). An Environment is **compatible** with an Operation when it declares them all; the catalog and the Environment page show it as ✓ / ✗ with the missing names.
- A live Plan is engaged **on** one Environment. At admission the Runner receives its values; that is the only way an Operation learns where to run or which service to call.
- A dry-run delegates no Environment value: nothing external runs.
- <Term id="credential">Credentials</Term> are stored **write-only**: a value can be set or replaced, never read back or displayed. Operations never contain secrets — the compiler refuses a source that looks like it does.
- The interface has one **current Environment** (header). Operation runs, Plan engagements and runnable marks refer to it. It is a preference of the browser, never in the URL.

See [Environments in the interface](/docs/environments) for the screens.
